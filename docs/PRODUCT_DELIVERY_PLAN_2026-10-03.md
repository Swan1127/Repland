# Repland 产品交付计划

日期：2026-10-03（Asia/Shanghai）
状态：实施中。用户已授权先提交 GitHub 再执行；实际完成范围与验证证据见 [交付进度](DELIVERY_PROGRESS.md)。本文的目标和验收条目不等于全部已实现；授权配置已完成首轮真实 DeepSeek 连接、草案修改及已有事项安排验证，完整操作与失败矩阵继续验收。

## 1. 本轮目标

让目标用户无需开发者在旁解释，即可完成：录入真实事项 → 制定计划 → 确认 → 开始执行 → 确认结果 → 重新安排剩余工作。

产品承诺：收下要做的事，生成能执行的计划，被打乱后还能重新安排。

产品场景包含课程和作业安排。此次交付限定为单设备 Android 工具，不扩展账号、云同步或多端协作。2026-10-05 用户明确排除招募、7 天用户试用及类似用户研究；这些不执行，也不作为完成条件。保留代码、构建和工作流技术验收。

## 2. 已明确的功能方向

| 页面 | 职责与本轮交付 |
| --- | --- |
| 今日 | 显示当前/下一项、开始执行、结果确认、当天安排与完整日程入口。 |
| 任务 | 快速录入、编辑、筛选；右上角由语音入口改为自动排序，语音进入新增任务流程。 |
| 助手 | 对话框上方独立“制定计划”；“说出你的安排”输入区域下方保留“安排今天 / 新增事项”。 |
| 我的 | 统一管理类别偏好、AI 配置/开关、提醒和数据；默认简洁，详情按需展开。 |

- 自动排序：只提出并应用任务列表顺序，不改当前日程。
- 制定计划：读取现有任务，主动重新排序并排程；无需先执行自动排序，不依赖输入框正文，保留尚未发送的文字。确认前结果为计划预览。
- 安排今天：对话框下属的单日安排工作流，默认不影响其他日期；跨日影响必须单独展示。
- 新增事项：对话框下属的收集工作流，可批量创建；区分仅加入事项库和加入并安排。
- 调整草案：作为计划预览内的编辑/连续对话能力，不保留独立快捷按钮。
- 当前路线采用单一操作模式；三种参与模式的保留与联动从本轮方案中移出，已有数据兼容处理纳入实施任务。

## 3. 规则统一与交付边界

实施前将已确认用户要求同步到权威产品规格，统一 REPLAND_IDEA、CONTEXT、功能方案、README、AI/隐私/测试/发布文档。先建立“已实现 / 待验证 / 待开发 / 延后”能力表，再更新对外描述。

本计划是后续实施的阶段安排；页面交互细节参见 FEATURE_PLAN_2026-10-03.md，其中参与模式相关旧建议由本计划的单一模式方向替代。已复现缺陷继续记录在 BUG_TRACKER_2026-10-03.md。

统一规则建议：

1. 标题或简短事项即可收集；未知类别、优先级、时长和日期不由模型静默填成用户事实，必要默认值须可见、可修改。
2. 缺少可用时间时只给排序和补充入口，不假设用户全天有空。首次规划可通过一张简短补充卡填写日期、起止时间，立即用于此次排程，并让用户选择是否保存为常用时段。
3. 本地排序先采用主思路的 V1 因子作为统一候选规格：用户优先级 35%、截止紧急度 25%、计划日期 15%、执行/延期证据 10%、类别偏好 10%；AI 修正最多 ±5 分，失败为 0。M0 明确每项映射、未知值和同分规则，以案例验证后冻结；不同时保留旧的 45% 中性 AI 权重公式。
4. 权重是软排序，不允许用高分覆盖课程、固定事项、硬保护休息或锁定段。用户手动决定的优先级需要独立于数值分数处理。
5. 普通重排保留用户手动顺序；“制定计划”是明确请求重新排序的入口，允许提出新顺序，但展示手动顺序变化，确认后才替换。任何重新排序不等于授权解锁或移动固定事项。
6. 一次确认将排序、计划及其决策记录整体提交；批量新增并安排还应包含新任务。已确认版本产生提醒，草案不产生提醒。
7. 任务完成、延期、取消、执行反馈只来自用户明确操作，计时结束不自动完成任务。

## 4. 阶段安排与验收门槛

按 M0 → M1 → M2 → M3 → M4 → M5 推进。每阶段交付可检查的结果，前一阶段关键验收未通过，不继续扩大功能范围。现有能力应复用，缺项补齐，避免整套重写。

### M0：建立可信版本和产品基线

目标：明确当前交付了什么，并消除核心流程阻断。

- B01：统一上述产品规则、功能状态、版本描述及正式 BYOK 路线，移除矛盾文案。
- B02：在指定候选包复现 QA-001，覆盖课程、固定事项、休息的同轨/异轨尝试；未来修复保证冲突有反馈、操作失败可恢复。
- B03：每个分发包记录版本名、版本码、构建来源和 APK 哈希；设置页可查看版本，测试记录绑定具体 APK。
- B04：修正文档工作目录和命令，建立核心手动回归清单，明确已测与未测路径。
- B05：确认实际网络适配器、构建变体与设置显示一致；不支持远程能力的包不能让用户误以为已经可用。

交付物：统一规格、能力状态表、缺陷复测记录、可识别的候选包和回归清单。

验收：核心录入和排程路径无崩溃；冲突失败不丢输入、不改已有计划；同一 APK 可重复验证；旧数据升级不被清除。相关单元测试通过不替代设备工作流验收。

### M1：统一数据、排序和草案提交

目标：任何页面操作都能在其他页面看到同一结果。

- D01：统一任务、时间约束、任务顺序、当前计划和设置的读取来源，拆分页面中的业务协调逻辑。
- D02：独立持久化任务顺序；各筛选页从同一顺序筛选，不各自排序。
- D03：持久化可编辑 Proposal，保留目标任务引用、时段、变化、风险、未安排原因和用户决策；切页、重启均可恢复。
- D04：建立统一操作服务和确认事务，支持任务+顺序+计划的原子提交；提醒在事务成功后同步，失败可重试。
- D05：校验任务/计划/设置版本，旧预览不能覆盖新修改；重复确认不能重复新增。
- D06：自定义轨道持久化并可在日/周/月中一致显示；新模型迁移保留既有任务、课程和历史。

交付物：共用操作层、可恢复草案、顺序存储、迁移与事务测试。

验收：切页/重启草案仍在；模拟批量提交失败时无半成品；重复确认结果一致；修改任务后旧预览明确要求刷新；确认和恢复计划后页面与提醒同步。

### M2：完成本地一键制定计划

目标：不配置 API 也能完成首次规划闭环。

- P01：任务右上角自动排序，支持依据、调整、应用、取消和适用范围内的撤销。
- P02：独立“制定计划”读取已有任务，执行排序 → 硬约束检查 → 排程 → 预览；默认 30 天窗口，优先展示今日结果，其余日期可展开。
- P03：没有任务引导新增；缺时长/可用时间显示最少补充卡；容量不足列出未排入项、时间缺口及处理选项。
- P04：展示具体变化及简短理由，不默认展示复杂分数；支持修改、暂不安排、确认和取消。
- P05：对话框下“安排今天 / 新增事项”绑定真实本地工作流；不通过拼前缀假装完成操作。
- P06：“我的”类别权重变化影响新排序与新预览；当前确认计划保持至用户接受替换。

交付物：完整本地规划流程、任务排序入口、首用补充流程、跨页导航与反馈。

验收：输入框为空也能制定计划，已有未发送文字保持原样；确认前任务顺序和当前日程不变；确认后顺序与日程一起生效；缺信息和容量不足有可行动结果；单日安排不无声改动其他日期。

### M3：接入统一 AI 业务能力

目标：AI 使用真实数据提高建议质量，操作结果与手动页面一致。

- A01：将现有调试适配器整理为目标构建可用的 Provider；统一开关、服务、模型、连接状态、Keystore 密钥和发送说明。
- A02：统一必要上下文：任务、有效反馈、时间约束、当前计划/草案及偏好；不发送密钥或无关全库数据。
- A03：首批操作限定为任务查询、批量新增、制定计划、局部调整与排序解释；模型返回结构化操作，经过本地业务校验。
- A04：支持连续对话修改同一 Proposal，匹配已有任务引用，避免把“修改”当成“新建”。
- A05：支持取消、超时、错误密钥、格式异常和本地降级；关闭 AI 或换配置后旧响应失效。
- A06：只在真实提交成功后显示实际影响数量和跳转入口；失败显示原因并保留输入。

交付物：统一 Provider 和 AI 上下文/操作契约、对话工作流、失败矩阵验证。

验收：有真实有效配置的目标构建完成一次远程规划；关闭/未配置时零模型请求；输出不能覆盖硬约束或伪造任务状态；错误响应不写入；相同操作经助手和页面执行得到相同业务结果。真实联网验证安排在实施阶段使用授权测试配置，不在设计阶段调用。

### M4：完成执行与剩余工作重排

目标：计划能被使用，也能应对现实变化。

- E01：今日突出当前/下一项、开始按钮、待安排和待确认数量，完整日程作为次级入口。
- E02：执行会话绑定任务/计划实例；开始、暂停、恢复、结束及后台/重启恢复按现有能力补齐。
- E03：结束后提供继续、部分完成、完成或跳过；反馈简短，详细复盘可选。
- E04：根据用户确认的结果计算剩余工作，提出新 Proposal；完成任务后的未来工作安排处理保留历史。
- E05：恢复历史计划后同步各页面与提醒；提醒开关、系统权限和时间变更按实际确认版本生效。
- E06：去掉参与模式分支，采用简洁默认界面和可展开详情；旧设置迁移不能影响业务数据。

交付物：日常执行闭环、可恢复计时、结果记录、重排和历史恢复。

验收：时间经过不自动改变任务状态；部分完成能正确安排剩余工作；重启不丢会话；取消重排保留当前计划；恢复计划和关闭提醒均实际生效。

### M5：候选版本技术验收与交付

目标：核对候选包的技术可靠性与工作流一致性；不进行用户招募、连续试用或留存研究。

- V01：完成真机升级迁移、真实 PDF 导入、通知、深浅色、横竖屏、无障碍和日/周/月回归，按目标包记录。
- V02：已移出范围：招募及 7 天试用，不是待执行项或阻塞项。
- V03：用隔离测试数据检查“录入几件事 → 生成计划 → 开始一项”，记录操作卡点、缺项提示与反馈；不冒称真实用户研究。
- V04：用可重复的计划受扰样例验证重排、取消及恢复；区分算法错误、信息不足和操作困难。
- V05：汇总缺陷与技术验收限制，形成交付报告；后置竞品及交互建议只形成报告，不自动改代码。

交付物：候选包回归报告、工作流检查记录、已知限制和交付清单。

发布门槛：核心阻断和数据一致性问题关闭；关键路径在指定包通过；数据迁移和降级可用；功能描述与实际构建一致。没有真机等外部证据的项目如实标为未验证；不增加用户试用门槛。

## 5. 固定验收样例

使用隔离测试数据，不覆盖用户正式数据。至少保留以下可重复样例：

| 样例 | 输入与操作 | 应有结果 |
| --- | --- | --- |
| 首次规划 | 三项真实风格任务，时长不全，无时间模板 | 可保存；规划时只补缺项，未知项仍待安排。 |
| 约束与容量 | 有课程、硬保护休息、固定事项及超出空档的任务 | 受保护时段不被覆盖，缺口和未安排项可见。 |
| 主动重排 | 有手动顺序和锁定时段，点击制定计划 | 可以建议新顺序，明确差异；锁定不动，确认后整体应用。 |
| 对话独立性 | 输入框有未发送文字，点击制定计划 | 原文字保留且不参与本次请求。 |
| 并发编辑 | 生成期间完成任务或手动移动时段 | 旧预览不能覆盖最新状态，提供刷新。 |
| 原子失败 | 新增多项并安排，模拟中途写入失败 | 无部分新增/部分时段，输入和草案可继续。 |
| 设置联动 | 改类别偏好、关闭 AI、关闭提醒 | 新规划用新权重，无晚到远程写入，实际提醒取消。 |
| 执行变化 | 部分完成、临时跳过、重启 | 剩余工作正确，会话可恢复，状态只由用户确认。 |
| 无网络 | 请求超时/断网/响应无效 | 保留输入，明确失败，本地规划可继续。 |

## 6. 观察指标与判断方法

本轮仅记录技术工作流、可重复样例及必要的本地诊断，不招募观察用户，不加入远程分析 SDK。

| 指标 | 口径 | 用途 |
| --- | --- | --- |
| 首次规划成功 | 得到可解释结果并确认，区分列表计划与具体时段计划 | 判断首用是否走通。 |
| 首次规划负担 | 操作次数、主动填写字段数、耗时及需要帮助的点 | 找出配置和表单阻力。 |
| 计划采用与修改 | 生成后确认/放弃，修改的任务和原因 | 判断计划实用性，修改少不必然代表好。 |
| 实际开始 | 用户主动开始至少一项，不从时间轴推断 | 判断规划是否促进行动。 |
| 受扰后重排 | 用户遇到变化后能否独立调整并确认 | 判断产品核心价值。 |
| 可靠性 | 指定包的核心失败、数据丢失、部分提交、崩溃 | 决定候选包技术验收结果。 |

不设置七天独立使用天数或留存目标。样例任务完成仍必须依据明确操作，不能从时间流逝自动推断。

## 7. 本轮延期范围

- 账号、云同步、多端协作和外部日历双向同步。
- 三种参与模式、自由聊天、复杂长期画像、习惯系统和记忆曲线。
- 无范围限制的 AI 自动控制；模型直接操作数据库、长期自动改状态。
- 助手修改全局设置/执行高影响批量操作：在首批规划能力稳定后逐项开放，仍通过共用命令和明确确认。
- 商业化和规模推广：先收集实际价值及持续使用证据，BYOK 不等于面向普通用户的成熟商业方案。

## 8. 进度管理

每阶段按“规格确定 → 实施 → 相关自动化验证 → 指定包端到端验收 → 记录结论”交付。任务可标记未开始、进行中、待验证、通过、阻塞；完成必须附验收证据。

不在缺少开发投入、迁移范围和设备验证工作量时承诺日历工期。M0 完成后根据任务拆分估算各阶段，再安排日期；可以逐阶段批准实施，但不把记录方案视作已经批准修改代码。

首个建议实施批次为 M0，其次 M1。独立制定计划的新界面在 M2 与实际能力一起交付，避免按钮先上线、核心链路仍未完成。
