# Repland 受限规划 Agent 与 AI 接入计划

更新日期：2026-09-18

## 重排后的目标

Repland 的下一条主线是完成**受限规划 Agent**，并在不破坏本地闭环的前提下接入真实 AI。Agent 不是自由聊天页，也不是可自行执行的自动化机器人；它负责把任务、约束和已确认反馈转化为可解释的建议或计划草案。

用户仍是唯一可以确认任务状态、替换任务、修改初始优先级和接受计划的人。

```text
用户任务 / 约束 / 已确认反馈
  → 本地受限 Agent 编排
  → 本地规则检查与 AI 请求预览
  →（用户明确同意后）受控 AI 网关
  → 类型化建议或计划草案
  → 本地校验、解释和编辑
  → 用户确认
  → 新的计划版本或执行日志
```

## 当前起点

当前代码已经具备以下基础：

- 版本化、类型化的 `AiAdvisor` 请求/响应契约；
- 本地 no-op Advisor、AI 开关、首次授权和请求数据预览；
- 对任务理解、难度/时长、拆分、排序解释、重规划、每日总结等请求类型的本地校验；
- 当前任务数据最小化、锁定时间段/硬约束校验，以及本地确定性规划降级；
- 当前 MVP 不声明网络权限，且 CI 防止意外加入联网实现。

因此后续不重写现有契约或确定性规划器，而是在其上补齐编排、网关与用户确认路径。

## 阶段 1：完成本地受限规划 Agent

### 1.1 明确 Agent 的能力边界

Agent 仅接受明确的、类型化的工作请求：

- 理解任务与提取可编辑要点；
- 评估难度、时长、拆分和工作方式；
- 解释本地排序与容量风险；
- 根据用户已确认的反馈或未来约束变化生成重规划草案；
- 汇总每日回顾。

Agent 不拥有写入任务状态、初始优先级、当前计划、执行日志或提醒的能力。它只能读取经过筛选的上下文，输出建议数据或未确认草案。

### 1.2 建立工作流状态机

为每次 Agent 请求建立可观察的本地状态：

```text
Idle
  → PreparingContext
  → AwaitingConsent（首次或数据范围变更时）
  → PreviewingRequest
  → RequestingAdvice
  → ValidatingAdvice
  → ShowingAdvice / ShowingDraft
  → UserAccepted / UserDismissed / FailedFallback
```

- `ShowingDraft` 绝不是当前计划；只有用户明确确认后才调用现有计划仓储创建新版本。
- `FailedFallback` 必须显示失败原因，并继续提供本地确定性规划。
- 技术审计只记录请求类型、契约版本、结果码、耗时和本地校验结论；默认不记录原始任务正文。

### 1.3 构建本地 Agent 编排器

- 在 domain 层新增受限 `PlanningAgent` / workflow 接口，负责选择请求类型、构建最小上下文、调用 Advisor、校验响应与转换展示模型。
- 复用 `AiRequestFactory` 和 `AiAdviceValidator`，不让 Compose 页面直接拼接网络请求。
- 将本地确定性规划器作为每种失败场景的回退，而非另一条独立 UI 流程。
- 对“由 AI 决定”仅实现为一次、可见、可撤销的冲突授权范围；未实现前不显示会误导用户的入口。

完成标准：断网或没有 AI 服务时，Agent 仍能给出本地解释和草案；任何输出都不能越过用户确认。

## 阶段 2：真实 AI 服务端接入

### 2.1 服务端/边缘网关，而非 APK 直连模型

真实模型密钥只能存放在受控后端或边缘函数中。Android 客户端只调用 Repland 网关，不能包含供应商密钥、系统提示词中的私密配置或服务端管理凭据。

网关职责：

- 校验客户端契约版本、请求类型、同意状态和大小限制；
- 进行设备/账户级限流、预算控制、超时、重试和熔断；
- 将类型化请求转换为模型调用，并将结果重新约束为类型化响应；
- 只保留必要运营元数据；默认不保存原始任务正文；
- 输出可审计的请求 ID、结果码、模型版本和成本区间。

客户端接入只允许 HTTPS，必须增加证书/网络安全配置、超时、错误映射和显式的远程功能开关。现有禁止网络的 CI 检查应在网关与隐私审查通过后被有意替换为“仅允许批准域名和 HTTPS”的检查，不能简单删除。

### 2.2 必须先确认的外部决策

真实接入前需要产品负责人明确选择或提供：

1. 模型/网关部署方案与数据所在区域；
2. 服务端密钥管理方式与轮换负责人；
3. 是否需要账号，或采用匿名设备令牌和其生命周期；
4. 原始请求、运营日志、审计日志的保留期限与删除流程；
5. 内测预算、限流阈值、故障处理与人工支持渠道；
6. 更新后的隐私说明和首次使用同意文案。

这些决策未完成前，客户端只保留本地 Agent 和 no-op Advisor，不启用 `INTERNET` 权限。

## 阶段 3：Android AI 适配器与 UI

### 3.1 数据最小化与同意

- 每次远程请求都展示将发送的字段；默认仅包括当前任务的用户内容、必要的已确认反馈、当前任务的已确认工作段和本次问题相关的硬约束。
- 不发送无关任务、完整原始历史、导出文件、画像原文或用户尚未确认的草案。
- 用户可随时关闭 AI；关闭后不发出后续请求，本地规划继续可用。
- 更正后的执行反馈优先于被更正的旧记录。

### 3.2 建议与草案展示

- 任务理解、时长和拆分建议显示为可编辑内容，不覆盖用户标题、描述、初始优先级或目标。
- 排序解释显示主要理由和详细理由，不暴露不可解释的黑盒分数。
- 重规划结果必须以影响范围、移动的工作段、容量风险和未排入任务组成草案；确认前不更新当前计划或提醒。
- 每日总结仅基于真实用户记录，跳过回顾不推断任务结果。

### 3.3 错误与降级

- 网络错误、限流、服务端拒绝、契约不匹配和本地校验失败分别提示用户。
- 所有失败都回退至本地确定性规划，不伪造 AI 结论，也不丢弃当前草案或已确认计划。

## 阶段 4：测试、评估与内测

### 自动化测试

- Agent 状态机：同意、拒绝、取消、超时、断网、关闭 AI、失败降级。
- 最小化：无关任务和更正前旧反馈不能进入远程 payload。
- 安全校验：拒绝跨任务建议、状态命令、锁定段冲突、固定任务移动、无效时间段和过大响应。
- UI：预览、建议编辑、草案接受/丢弃、错误提示与本地回退。
- 服务端：鉴权、限流、预算、审计脱敏、密钥不出服务端、模型输出结构化校验。

### 评估指标

- 用户是否看懂并接受/编辑/丢弃建议；
- AI 请求成功率、延迟、限流率和本地回退率；
- 计划确认率、后续人工调整率、约束冲突拦截率；
- 单次请求成本和日预算；
- 零未经同意的网络请求、零未确认计划替换、零 AI 状态改写。

## 交付顺序

1. 审计并补齐本地核心闭环的缺口，确保 Agent 有可靠输入和确认出口。
2. 实现本地 `PlanningAgent` 工作流、状态机和完整测试，继续使用 no-op Advisor。
3. 完成网关部署、隐私审查和内测凭据配置。
4. 实现 Android HTTPS 适配器与受控功能开关，先在封闭内测中灰度启用。
5. 使用指标和用户反馈迭代建议质量；真实 AI 始终不能绕过本地校验和用户确认。

## 明确不做

- 不将真实模型 API key 写入 Android 工程、Gradle 属性、APK、导出文件或日志。
- 不用自由聊天替代受限规划工作流。
- 不让 AI、规则或系统自动完成、延期、取消、替换任务，或静默覆盖当前计划。
- 不把 AI 同意等同于云同步、画像、营销分析或账户授权。
