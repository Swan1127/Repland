# Repland 产品与交互意见报告

日期：2026-10-11（Asia/Shanghai）。本报告在本机候选技术验收通过后形成，建议仅供后续决策，没有据此新增功能。

Repland 的分析对象为 `codex/placement-numeric-integrity`，源码提交 `32d766f95224b3851dbb832bd9644b541b3436cf`；实际安装版本为 **0.1.35-internal / 1035 / Room 21**。261 项源码 / 构建输入与验收清单一致，安装 APK 与最终 internal 哈希一致。当前生产源码的 150 项 JVM 测试、最终 310 项 QA 设备测试通过；设备测试包括仓储、组件和实际 Activity，不等于全部人工工作流或真机通过。`.current` 另有真实模型生成、未确认隔离、草案冷恢复、确认回执与日程一致的实际证据。详见[最终技术验收](FINAL_TECH_ACCEPTANCE_2026-10-10.md)和[可携带证据](verification/final-0.1.35/README.md)。

竞品资料均为 2026-10-11 查询的官方页面；没有对竞品进行设备实测，不比较其实际稳定性、模型效果、价格或使用收益。下文明确区分官方说明、Repland 实测事实和分析建议。

**1. 当前定位**

Repland 当前适合定位为单设备 Android 个人任务与时间规划工具，兼顾课程、固定事项、可用时间和临时任务。用户先保存事项，再查看可编辑安排，确认后进入正式日程；主动开始或明确补录才形成执行证据。AI 可通过用户配置的服务提供有限建议，正式数据仍由本地业务校验与确认流程写入。

已有价值集中在输入、计划、执行和来源的一致性：未知信息可保存，受保护时间不被普通重排覆盖，历史恢复保留事实，画像数值可查来源。当前交付不包含账号、云同步或团队协作；数值画像完成的是权威计划允许的首批三个维度，完整扩展目标仍待实施。

**3. Repland 已有优势**

- 输入与证据边界清楚。标题或一句事项可保存；未知类别、优先级、天数等不会因保存而变成用户选择。`.current` 真实模型确认后的任务仍显示未知字段，已知的 30 分钟安排单独展示。
- 计划变更有可检查的提交边界。QA 已覆盖排序与日程隔离、保护拒绝、历史恢复、过期草案及失败回执；真实模型草案冷恢复后确认得到“新增 1 / 写入 1”，与日程一致，任务仍未开始。
- 数值采用程序计算和来源追溯。首批估时系数、执行段和类别偏好支持来源、排除 / 停用及有限建议。当前实际任务没有执行证据，估时与执行段保持 0 样本未知，默认类别权重明确标注。
- 本地失败处理已有针对性验证。课程与精确时间保存失败保留输入，事务成功后才关闭，保存途中重建也有实际 Activity 测试。原位升级保留本机数据与已保存配置。

这些结论是当前实现和验收范围内的工程能力，尚不能推导出更高完成率、更准确长期估时或优于竞品的用户收益。

**4. 当前不足**

真机升级、完整历史 1→21 用户库、自然到点闹钟 / 重启 / OEM 后台、真实 PDF / 语音 / 系统文件和完整无障碍矩阵仍缺外部证据。QA-062 / QA-066 / QA-067 / QA-072 的间歇问题根因未定位，最终全套通过没有关闭这些 P2 风险。

真实模型只验证了当前提供方的指定安排流程；数值画像 AI 描述尚无真实成功证据。当前无有效执行样本，不能通过制造执行记录补足。后三画像维度保持未知，主创建 / 编辑表单内嵌建议、细粒度增量与大数据性能尚未完成。现有数值是局部记录的统计参数，不能解释为人格、能力、自律或健康评价。

QA 合成数据比较中，必要证据为 2872 字节、参数载荷为 354 字节，并保留指定事实一致性；这仅支持该夹具的载荷大小结论，不证明真实服务 token、费用或描述质量提升。[比较记录](verification/final-0.1.35/numeric-payload-comparison.json)

**5. 用户工作流问题**

| 已观察事实 / 已知限制 | 可能造成的理解或操作成本 | 证据与边界 |
| --- | --- | --- |
| 真实模型候选生成后，需要向下滚动才能到达最终确认；本次操作使用了两次上滑 | 用户可能已看懂候选，却仍需寻找提交入口 | `.current` 本次实际操作；未测所有候选长度、屏幕和字号 |
| 自动排序、制定计划、安排今天、新增事项分别承担不同操作 | 正确的数据隔离仍需要清楚的入口说明，避免用户误解“排序”为改日程 | 隔离自动化通过；首次使用者的理解成本为分析判断，未做用户研究 |
| 缺少可用时间或必要时长时，流程需要补信息或暂不安排 | 用户需要知道最少补哪一项，以及补完从哪里继续 | 现有缺信息 / 时间设置工作流与测试；不建议伪造默认时长 |
| 画像从“我的”进入，数值和来源纵向展开，来源详情包含内部标识和时间值 | 首屏重点可能被技术信息分散，逐项追溯需要更多滚动 | 已查看画像数值、未知与来源页面；密集来源操作由 QA 合成数据验证 |
| 有 JSON 导出，完整导入恢复尚未提供 | 用户可能把“备份”理解为能够完整恢复 | S07 源码与功能文档；系统文件选择全矩阵未验证 |

**6. 交互优化建议**

优先复用现有 Compose / Material 3 组件，改善既有路径的可见性。候选确认区可考虑常驻展示本次新增、调整和时段数量，并提供查看差异入口；仍须由用户主动确认，确认前重检约束。保存失败继续保留原输入，成功反馈只使用真实事务结果。

缺信息提示应说明当前缺什么、为什么需要、最少下一步是什么，并保留“先保存事项”的路径。排序入口提示“仅调整任务列表”；制定计划展示“读取已有任务生成草案”；输入区域的安排 / 收集动作保持一致称谓。是否采用这些文案，需要结合实际页面空间单独评审。

画像首页可优先呈现数值、样本数、时间范围及“未知 / 仅供参考 / 可用于建议”状态；来源详情先显示用户可理解的事项、日期、执行或补录来源，再按需展开内部标识。当前无样本时说明统计边界与合法来源即可，避免把开始任务变成填充画像的诱导动作。

数据导出应准确说明内容与恢复能力；完整恢复需要另行评估和验证。保留对未确认草案、正式计划和执行事实的区分，不为了减少点击而合并授权边界。
