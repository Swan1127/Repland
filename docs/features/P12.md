## 功能目标

连续补充指令修改同一草案。沿用当前单一模式与现有能力，不恢复旧三模式入口。

## 用户操作入口

`AgentProposalPanel` 的 follow-up。页面归属：助手 / 规划预览 / 我的计划历史。

## 前端页面位置

`AgentProposalPanel` 的 follow-up。当前源码：[AgentCenterScreen.kt](../../android/app/src/main/java/com/swan1127/repland/ui/agent/AgentCenterScreen.kt)、[PlanViewModel.kt](../../android/app/src/main/java/com/swan1127/repland/ui/plan/PlanViewModel.kt)、[PlanningOperationService.kt](../../android/app/src/main/java/com/swan1127/repland/domain/model/PlanningOperationService.kt)、[RoomPlanRepository.kt](../../android/app/src/main/java/com/swan1127/repland/data/room/RoomPlanRepository.kt)。以组件与回调名定位，避免沿用历史行号。

## 业务逻辑

CompatibleArrangementAdvisor、身份验证。实际入口只触发对应业务操作；正式数据变化须通过校验与真实提交回执。

## 数据来源

PlanningReadService 的任务、约束、当前计划、执行与版本快照；候选单独保存，未确认信息不能作为画像证据。

## 数据流转

用户发起 → 读取完整快照 → 本地规划 / 有限远程建议 → 可编辑且本地保存的草案 → 确认前复检版本与保护约束 → 原子提交 → 实际数量回执。查询与解释没有写权限。

## 持久化方式

Room 21 中的正式计划 / 历史、独立任务顺序、规划 draft 与助手 workspace 分离。编辑草案比较原预览并原子替换；正式提交前重检来源修订。

## AI 参与范围

仅在明确发起、授权与目标构建支持时使用对应有限契约；AI 不直接操作数据库。建议 / 描述不成为未经确认的字段或执行证据；失败和关闭的本地路径独立验收。
