# C07：不可避免跨路径保护与相关确认工作流

更新：2026-10-09。本批接续 C04，复用本地生成器、PlanningOperationService、Room 事务与 Compose / Material 3 组件，不开发 H01–H06 数值画像。本文件应与 [接手基线](../PROJECT_BASELINE_2026-10-09.md) 区分：基线记录修改前状态，本文件记录本批实际修改。

## 规则与实现

| 范围 | 修改与用户可见行为 |
| --- | --- |
| 不可避免排序 | 没有手动顺序时，未安排的 REQUIRED 在普通任务之前参与分配；没有可用时间仍保留未安排原因，不编造固定时段。独立列表排序仍不改变当前日程。 |
| 已确认时段 | `Plan.kt` 的直接生成、剩余重排及仅今天范围保留不可避免的日期、起止、轨道；临时生成保护不写成用户锁定。`PlanningAgent.kt` 的本地降级和 AI 安全基线使用同一重排入口。 |
| 草案来源 | `PlanningOperationService` 拒绝无来源版本的旧草案，保留原草案供查看 / 重生成；AI 规划及降级草案携带生成时完整 revision，包含独立列表顺序，确认时不能用当前版本替换旧来源。 |
| 最终写入 | `RoomPlanRepository.acceptInTransaction` 拒绝移动、删除活动任务尚未结束的不可避免时段；未来保留片段也重检新硬约束。修改前的 AI 有限契约继续适用。 |
| 普通重叠 | `PlacementValidator` 对任何轨道统一检查；手动 `ManualPlanChange` 先检查课程、固定事项、休息、锁定与不可避免保护，再提供普通重叠的单独确认。确认不创建执行记录或改变任务状态。自动 / 助手写入不能使用手动重叠例外。 |
| 主动调整 | 不可避免的移动、移除或清空需单独确认。确认携带完整规划 revision，在事务内重读；任务、约束、排序或计划变化后旧确认拒写。锁定和运行中的任务先解除锁定或结束专注，不能凭确认直接绕过。 |
| 历史管理 | 我的 → 计划历史与锁定管理。锁定、移动、移除、清空写新版本，旧版本保留。恢复前说明仅恢复排序/安排；失败在历史面板内显示并保留面板。原有结束任务过滤与执行证据保护继续使用。 |
| 时间编辑 | 精确编辑详情可滚动、完整展开；普通重叠交由事务请求确认，硬约束冲突有明确说明。确认对话框显示任务、拟议时间/轨道和具体原因，取消零写入。 |

`ManualPlanChange.kt` 定义有限业务操作；`PlanViewModel` 保留待确认操作及失败信息，事务失败允许同一 revision 重试。确认只针对明确操作，不能授权其他写入。手动计划操作不清除未确认规划草案，草案仍由现有 revision 机制拒绝覆盖新事实。
