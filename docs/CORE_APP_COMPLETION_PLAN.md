# Repland 核心功能完成计划

更新日期：2026-09-18

## 目标与边界

最低交付标准不是接入真实 AI、账号或云同步，而是让用户在单台设备上可靠完成以下闭环：

```text
录入任务和时间约束
  → 生成可查看的计划草案
  → 用户编辑并确认计划版本
  → 按计划执行并提交真实反馈
  → 生成新的调整草案
  → 用户确认后继续执行
```

整个闭环必须离线可用。AI 只可提供可预览、可丢弃的建议；不允许自动完成、延期、取消、替换任务，或未经确认替换当前计划。

## 与 Agent/AI 主线的关系

本地核心闭环仍是受限规划 Agent 的可靠输入和用户确认出口。Agent 与真实 AI 的构建顺序、网关边界和接入门槛见 [AGENT_AND_AI_INTEGRATION_PLAN.md](AGENT_AND_AI_INTEGRATION_PLAN.md)；本文件继续定义本地核心功能的最低完成标准。

## 实施顺序

### 阶段 0：现状审计与基线

- 按 `CONTEXT.md`、`README.md` 与开发路线图逐项核对现有实现、数据库迁移、UI 和测试。
- 建立“已实现 / 缺口 / 已验证”矩阵，只修改与核心闭环直接相关的代码。
- 在每次改动前后运行构建和相应测试，保留现有用户改动与历史数据。

完成标准：确认真实缺口，不重复实现已有能力，也不扩大到云端或自由聊天。

### 阶段 1：任务与可追溯执行记录

- 核对任务创建、编辑、初始优先级保护，以及未开始、进行中、完成、延期、取消、替换的用户确认流程。
- 核对部分完成、实际耗时、进度、完成内容、结果、延期原因和更正日志。
- 确保替换、恢复、历史计划回退都只追加新记录，不覆盖任务、计划或执行日志。

完成标准：用户可从任务详情按时间顺序还原状态和反馈；Room 升级不会丢失既有数据。

### 阶段 2：时间约束与用户确认的计划

- 核对每周时间块、单日例外、单双周、课表 PDF 导入预览和用户锁定工作段。
- 核对本地 30 分钟粒度排程器：缺少可靠时间信息时只输出排序清单；有约束时不得与课程、休息、锁定段或固定任务冲突。
- 核对草案展示、排序/工作段编辑、确认、丢弃、历史查看和恢复语义。

完成标准：未确认草案不影响当前计划和提醒；每次确认都形成新的可回退计划版本。

### 阶段 3：执行反馈与调整草案

- 核对已结束工作段的“待确认”状态，确保系统不把时间结束推断为成功或失败。
- 提交完成、延期、部分完成或未来约束变化后，只生成调整草案；计算剩余工作但不静默移动当前计划。
- 核对多次延期提示重新评估目标、拆分或改期，但最终仍由用户选择。

完成标准：计划被打断时，剩余工作、原计划版本和历史反馈均保留，新的安排必须经用户确认。

### 阶段 4：行动支持与本地数据控制

- 核对本地提醒只来自已确认计划，并在确认、回退、取消和关闭提醒后正确同步。
- 核对每日回顾显示真实完成、耗时和进度；跳过回顾不得改变任务状态。
- 核对画像证据可查看、修正、删除；本地 JSON 导出和确认后的本地清除行为正确。

完成标准：提醒和复盘不强迫用户，数据可导出、可清除、可解释。

### 阶段 5：核心路径质量门槛

- 为发现的缺口补充领域单元测试、Room migration 测试、Repository 测试和 Compose/UI 仪器测试。
- 在 API 26 与当前 API 36 模拟器回归任务录入、草案确认、反馈、提醒、PDF 导入和升级迁移。
- 构建 debug 和 internal 包；检查隐私边界、离线降级、签名和混淆后的 PDF 导入。

完成标准：核心路径自动化通过；真实设备清单中不依赖账号、网络或未确认草案。

## 工作方式

每个阶段均遵循以下节奏：

1. 阅读对应代码和现有测试，记录事实与缺口。
2. 在现有架构上做最小化修改。
3. 先为关键规则补测试，再运行受影响的单元与仪器测试。
4. 向用户报告完成内容、未覆盖风险和下一阶段，不把未验证能力描述为已完成。

## 不在核心完成标准内

- 真实联网 AI、模型密钥、受控后端、账号、云同步、协作。
- 长期目标模块、完整习惯教练流程、外部日历或课程系统同步。
- 未经单独产品决策的自动状态变更、自动重排确认或用户画像结论。

这些能力只能在核心闭环稳定、隐私与授权要求明确后，按 `EXTENSION_READINESS.md` 单独开展。
