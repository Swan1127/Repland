## 提示词正文

你是一名兼顾产品设计、交互设计与客户端实现的工程师。请在我此次拉取的最新 Repland 上，完成前端视觉与交互重构、真实能力接入、实际运行验证和交付。根据新版本的功能与数据契约重新组织页面，同时落实下述统一的视觉和动效规范。

目标覆盖页面构图、主题、组件、点击反馈、页面与面板过渡、表单操作、数据变化、异常状态和返回恢复。优先让用户快速找到当前行动、理解自动调整的实际结果，并能连续完成操作和返回。请完成实际实现，并以可运行结果和真实操作证据交付。

Repland 的核心是个人任务规划与执行：收集事项、结合真实时间约束安排、记录执行、在变化后修复计划。围绕“现在做什么、接下来怎样安排、变化后如何调整”组织体验。参考里的天气、旅行、银行卡、支付和登录用于理解形式，功能范围以新版项目为准。

### 二、先适配新功能与真实能力

建立“功能 → 用户操作 → 页面/组件 → 数据来源/接口/本地能力 → 权限与状态 → 成功/失败反馈”的对应表，标明继续使用、需要调整、已移除与尚未接入的能力。

集中处理数据模型到展示模型的转换。字段名、必填项、枚举、空值、分页、优先级、日期与时区、预计与实际时间、撤销范围、冲突及部分成功均按新契约解释。显示值、统计、状态、进度和可用操作具有真实依据。

新功能有合理入口和完整状态；已删除的能力清理入口与说明；替代流程保持连贯。缺失能力写明具体依赖，不能使用示例数据、空按钮或伪造回执制造已接入的效果。演示数据与真实使用分离并标注。

整体方向是温和、清晰、有少量风景氛围的个人时间工作台：浅暖中性环境、白至奶白内容面、深色文字、淡青与薄荷功能色，少量灰绿、陶土、丁香和雾蓝形成风景层次。

统一三个层次：安静的页面环境、承载信息的卡片或连续内容面、承接当前操作的详情或面板。首页焦点、少数主题封面、个人头部与空状态可以使用简化山形、地平线、日月和柔和渐变；日程、列表、表单、总结和设置以信息清晰为主。

日常操作区保持浅色填充、深色文字和清楚的主次关系。墨青主要用于文字、图标与插画深景；避免深色大按钮和大块高饱和背景压过内容。主要按钮使用统一的浅薄荷底与深色字，次要动作采用中性色描边或文字。危险操作有独立语义和必要提示。

日程以浅蓝作为功能强调，任务以薄荷为主；我的与设置共享淡青/灰绿体系。紫粉可小面积融入统一插画，不能把资料、总结标题与总结页脚分别拼成不同色块。总结和设置正文使用中性内容面，风景渐变不铺到长段正文背后。

任务颜色通过有限的业务类别或语义映射确定，同一对象在切页、排序、刷新、重启后保持一致；不按任务 ID 散列生成任意彩虹卡片。稳定 ID 用于对象标识、状态恢复和动效关联。优先级、状态、保护与风险配合文字或图标，不能只靠颜色。

普通正文与次要文字在实际背景上的对比度至少 4.5:1；有意义的图标和控件边界检查至少 3:1。检查渐变、遮罩和按压后的实际合成画面，不以少数色板锚点代替全部状态。深色模式定义独立的深墨青环境、对应内容表面、浅色文字和克制强调色；系统动态取色应遵循明确一致的主题策略。

### 四、规格、排版与共用组件

图片中的组件墙用于学习大小比例与层次，真实页面按用户操作顺序组织。每页保留一个主要视觉焦点，日程时间轴和任务列表保持方便扫描的密度。普通事项优先使用紧凑行与统一承载面，当前行动和重点内容才使用更明显的卡片与局部风景。通过布局、字号、填充、描边和留白建立主次，避免所有模块具有相同大小、阴影与强调程度。

手机侧边距建议 20dp，窄屏可为 16dp；采用 4/8dp 间距体系，内容内距约 16–20dp，组间距约 24–32dp。重点外卡片圆角约 24–28dp，普通内容卡约 18–24dp，输入与按钮约 12–16dp，小标签使用更小圆角。阴影柔和、接触感轻，边界用于表达实际层次。

使用中文友好的系统无衬线字体。正文约 15–16sp，辅助说明约 12–14sp，分组标题约 18–20sp，页面标题约 28–32sp，按内容和字体缩放调整。主要内容左对齐，时间与数字对齐；长标题、说明与按钮文字合理换行，控件随内容增高，避免裁切、重叠和孤立尾字。其他技术栈使用对应的可缩放单位，不把 dp/sp 当成固定像素。

形成共用的页面容器、焦点卡、分组卡、日程项、任务项、图标底、导航行、开关行、主次按钮、筛选项、表单、面板、空状态与错误反馈。图标使用一致的矢量系列，风景插画与功能图标分别承担氛围与操作职责。

保留原生点击、开关、焦点、禁用和无障碍语义。图标按钮提供可读名称，紧邻文字的装饰图标不重复朗读。Android 点击范围至少 48dp，其他平台遵循相应规范；视觉缩放不改变点击范围或挤动布局。

处理状态栏、底部手势区、固定导航和软键盘遮挡。窄屏与大字体优先换行、增高和压缩装饰；横屏与平板使用受控内容宽度或列表/详情双区，避免长说明横贯整屏。

### 五、页面组织：按新版能力落地

以下页面以旧版“日程、任务、我的”和相关助手、设置为参考。仅对新版仍支持的能力适用；新版已删除或替代的模块同步调整，不为复刻参考重新创造旧功能。导航可按新业务重组，常用操作容易发现，避免所有能力都挤进导航或设置。

**日程与首页。** 保持清晰日期、必要的新建入口、日期范围/视图切换、时间侧栏与真实事项。可将原本占地较大的新增区域改成紧凑的“当前 / 下一行动”焦点卡，展示真实任务、时间与可用动作，风景置于侧方或背后。焦点区建议控制在首屏可用高度约四分之一以内；内容多或字体变大时减少装饰，尽早露出真实日程。无安排时提供真实空状态与可执行入口。

焦点卡优先呈现真实进行中的执行会话；没有会话时，根据现有规则展示当前可行动事项或下一项安排。不能仅因已到开始时间就标为“正在执行”，此时可准确表述为“当前时段安排”。卡片保留标题、必要时间、状态和一个主要动作，其余操作放次级区域。主动作由真实状态与契约决定，新建和一句话处理仍清楚可达。已结束时段可折叠并允许展开，不据此推断任务完成。

若保留日/周/月与总计/详细，按层级组织并保持位置稳定。总计按真实时间拆分重叠区间，详细呈现完整事项；排序、分组与优先级以新契约为准。点击时间片回到对应原始事项和具体安排实例；切换展示不写入计划、不改变状态。固定事项、保护与优先级清楚可辨。

**日程容量与冲突说明。** 在现有领域能力与可信数据支持时，用简洁的时间说明表达剩余容量、超出时间和估时完整性，并连接真实可用的冲突查看或调整入口。例如“今天还可安排约 80 分钟”“按现有估时超出可用时间 40 分钟”“两项任务尚无估时，结果不完整”；这些只是文案示意，数值必须来自实际计算。

沿用领域层的容量口径，考虑固定安排、休息、保护、锁定、重叠、当前执行及日期时区，避免重复扣除同一时间。区分规划估计和真实耗时，缺失估时不按零处理。前端不另写一套调度或容量算法，也不以无依据的综合评分替代时间说明。新版尚无可靠数据或接口时，说明具体依赖，完成已有能力支持的呈现，不虚构精确容量。快速查看日程无需经过强制每日规划仪式。

**任务与详情。** 使用统一的奶白列表或卡片、淡薄荷/灰绿辅助与清楚的标题、状态和必要元信息。重点任务可有克制的主题封面，普通任务保持紧凑。新版实际支持的筛选、搜索、排序、新建与空状态使用相同规范。

详情按“核心信息 → 业务内容、安排、进度或记录 → 可执行操作”组织。动作和可用性来自新契约，不固定复制旧版完成、部分完成、推迟或反馈按钮。主次与危险操作清楚区分，阅读或编辑时压缩装饰。

标题保留一个主要呈现位置，首屏集中展示状态、关键时间与当前主要操作。备注、分类、估时、安排历史和执行记录按需展开；未分类、未设置和未知值不作为多行占位信息挤占首屏，但保留编辑入口。影响当前操作的缺失信息在相关位置说明，空白或未知不能解释为零。删除仅表达实现结构的重复标签，例如没有用户用途的“任务上下文”“可回溯”，改用用户能理解的内容标题。

复用现有待安排分类，清楚区分任务已收集与已安排到具体时间。快速记录允许按当前契约保留尚未补全的事项，不为视觉完整强制填写图标、分类、估时或日期；需要补充的内容在实际安排或操作时适当引导。

**一句话处理或新版助手。** 若保留该能力，入口清楚并与来源页面有关联；打开后使用统一面板。输入、处理中、实际结果、失败和撤销状态清楚，结果先解释发生了什么，再提供原因或依据。保留草稿，避免用持续跳动的聊天装饰制造工作假象。授权内直接执行、仅建议与越界决策按新版规则呈现。

结果明确区分“已记下，待安排”“已安排到具体时间”“未执行/失败”，仅在契约允许且实际发生时显示部分成功。依据真实事务结果展示新增、调整数量、关键日期时间、未处理内容及原因，不把整次失败说成已保存。授权内操作不因新增结果卡片而增加重复审批。

调整回执可以再次找到：优先复用现有操作记录、历史或来源事项的结果入口，不能只依赖几秒后消失的提示。回执可按能力提供“查看变更”“查看依据”“撤销”，展示实际变动及必要的前后时间。撤销范围、时效和冲突保护遵守当前契约，不承诺所有操作都可撤销；不可撤销时解释原因。契约尚不支持持久记录或相应操作时，明确缺口，不伪造历史或放置空按钮。

例如“已安排明天 14:00–14:40，同时顺延两项任务；查看变更 / 撤销”仅作表达示意；数量、时间、固定安排是否受影响以及撤销是否可用，都必须来自实际结果。

**我的与个人资料。** 与设置共用淡青/灰绿色系。若保留个人资料，将头像、用户名、明确编辑入口与轻量风景头部组合，正文以中性内容面承接。选择取消、保存失败与重试保留原值；键盘不能遮挡保存和取消。

头像规格、用户名校验、图片选择、上传、本地保存和云同步以新契约为准。显示实际保存与同步状态，不把本地成功说成云同步。若保留自动总结或画像，展示基于真实记录的摘要、必要时间、状态和依据入口，用留白、文字与细分隔线区分内容，不使用多色大背景拼接。

**设置与子页。** 可参考“日常使用、智能与个性化、数据与隐私”分组，按实际能力调整；不保留空分组或重复入口。统一圆角内容面，标题可用小面积相近淡色渐变，正文保持中性。普通入口为“图标 → 标题/说明 → 箭头”，开关为“图标 → 标题/说明 → 原生开关”，对齐图标、文字和操作列。

高级选项按需展开，状态明确，避免重复标题。说明贴近相关控件，授权与模型实际能力清楚可见，版本信息置底。读取失败、保存中、保存结果与校验错误分别处理，不能用默认值覆盖尚未读取的真实设置。设置以信息效率为主，减少插画。

### 六、运行时动效与空间连续性

先给关键流程写出“来源状态 → 用户动作 → 中间变化 → 目标状态 → 返回/中断”的简短分镜。优先打磨三条完整链路：列表到详情及返回；重新安排到受影响事项迁移、回执与可用撤销；助手打开到键盘输入、处理结果及关闭。每个变化让用户知道操作对象去了哪里、什么数据改变、下一步能做什么。

优先完成“日程/任务卡片 → 详情 → 编辑或执行 → 返回”的完整流程。选中卡片或关键视觉元素向详情头部延展，色面、边界与圆角协调变化，正文在承载面稳定后呈现。返回恢复来源上下文、筛选和滚动。文字使用清晰布局与淡入承接，避免将长段正文拉伸。当前依赖不支持共享元素时，用对齐来源位置、统一色面与短距离定向过渡实现连贯感。

页面导航按固定顺序决定方向，底部导航位置稳定。筛选主要移动选中指示，数据区只更新相关内容。面板从触发区域或合理方向进入，遮罩与内容协同建立层级；关闭后还原来源，焦点回到触发入口。

助手的输入框、键盘、面板与结果区同步调整，输入和提交动作保持可见；提示内容在输入时适当让位，避免键盘与扩展面板叠加。按平台与项目既定规则区分收起键盘、关闭局部面板及离开助手，返回与失败保留草稿。处理完成后平稳呈现实际结果，避免列表突然跳动或输入被新结果顶出屏幕。

若保留总计/详细切换，保持日期、选中对象和上下文稳定；安全映射的可见事项平滑改变位置或形态，其余部分使用局部显隐。任务可能有多个安排与时间片，过渡标识区分真实实例；共享过渡只绑定唯一选中对象。

完成、进度、重新安排与撤销以真实提交结果驱动局部反馈。只让受影响事项平滑迁移，保持未变化事项与用户滚动位置稳定，回执说明实际变化并按能力提供依据或撤销。范围较大时突出变化，不能因为动画结束就判断保存成功；动效本身不得触发安排、完成或统计写入。

以下为一套统一默认值，可按距离和内容复杂度小幅调整；数值是实施建议：

| 场景 | 默认节奏 | 配合方式 |
| --- | --- | --- |
| 按下 / 松开 | 90ms / 140ms | 约 0.98 视觉缩放，保留原生涟漪、焦点与点击范围 |
| 同层切页 / 筛选 | 280ms | 约 8–20dp 定向位移与局部显隐，导航稳定 |
| 卡片进入详情 / 返回 | 约 340ms，可在 280–380ms 调整 | 主要承载面先变化，标题与关键时间承接，正文随后出现 |
| 面板展开 / 关闭 | 280ms / 200ms | 与遮罩协调，关闭恢复来源上下文 |
| 分组展开 / 收起 | 260ms / 180ms | 高度、箭头和内容显隐协同，可中途反向 |
| 状态与进度反馈 | 约 200ms | 仅相关对象响应，最终值清楚 |

主过渡自然减速，短反馈可轻微弹性。一个动作一个主要运动，配合少量承接；必要内容错峰约 20–40ms，整组及时可用。避免整页所有卡片逐个飞入，操作当下立即触发应有动作，不等待动画结束再提交或请求。

快速连点、切页、展开途中收起、打开途中返回时，从当前视觉状态更新目标或取消旧过渡，不排队播完。退出内容不继续接收点击；动画、重组和重复事件不能造成重复请求或写入。

风景可在进入重点区域时有一次轻微相对位移，随后安静停留。输入、阅读、滚动与专注期间减少装饰运动；不持续漂浮、闪烁或循环制造背景负担。尊重 Android 关闭动画与项目减少动态效果设置，直接显示稳定目标状态。新版如确为 Web，再使用相应的 `prefers-reduced-motion`。

### 七、真实状态、业务保护与可靠性

主要流程按实际需要覆盖首次加载、空数据、有数据、局部刷新、提交中、成功、失败重试、权限不足、冲突与模型不可用。联网能力还处理断网、超时、认证失效、分页和部分成功。

读取失败与确实无数据区分；刷新保留已显示内容和位置；提交中防重复且保留输入；失败在相关位置给出原因与重试，不关闭后丢失草稿。成功以实际结果为准，乐观更新有失败回滚。处理过期响应，避免旧结果覆盖新输入或新页面。

任务、安排实例、轨道、预计时间、实际执行与授权范围按当前模型解释。对新版仍保留的固定事项、课程、硬保护休息、锁定段及执行会话，遵守其现行保护规则；事务、幂等、版本校验与撤销按当前契约维护，不重新引入已删除的旧模型。未经真实操作不推断完成或实际耗时，不因时间经过自动完成任务。

授权内自动执行和需要决策的情形以最新有效规范为准，不把旧版审批流程套回全部操作。无网络或无模型时，已有本地能力继续可用；未满足远程授权时按实际能力反馈。前端不自行制造后端未确认的规则、成功或统计。

新契约缺失时指出字段、接口或能力的具体缺口，并完成其他明确部分。配套领域或后端改动按本轮需求范围处理，不能用旧逻辑替代新契约。

本轮前端重构不自行改变领域模型、任务选择与调度口径，也不扩张自动执行授权。焦点卡、容量说明、回执和动效均消费真实状态；如确需配套业务调整，应明确其依据、范围与依赖，不能藏在视觉改动中。
