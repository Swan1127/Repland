## 提示词正文

你是一名兼顾产品设计、交互设计和 Android 客户端实现的工程师。请在我已经拉取的最新 Repland 项目上，完成一次完整的前端视觉与交互重构，包括页面构图、主题、组件、真实状态和运行时动效。请阅读附件参考图片与视频学习结论，将它们转译为适合 Repland 的统一体验，并完成实际实现与运行验证。

### 1. 先建立当前项目事实

先检查当前仓库的 AGENTS.md、README、近期变更、产品规范、实际页面、主题、导航、状态管理、数据模型与测试，简要说明本次准备调整的页面和共用组件，然后继续实施。

已知的旧快照为 2026-10-18 的 Kotlin / Jetpack Compose / Material 3 原生 Android 项目，使用 ViewModel、Flow、Room。它只是背景资料；开发基线必须是我此次拉取的代码。优先使用当前技术栈与既有架构，不预设 React、网页或 Tailwind，不为改视觉迁移框架。若最新项目已有变化，以实际代码和最新有效需求为准。

Repland 的核心是个人任务规划与执行：收集事项、结合真实时间约束安排、记录执行、在变化后修复计划。请围绕“现在做什么、接下来怎样安排、变化后如何调整”组织界面。参考中的天气、旅行、银行卡、支付和登录功能只用于理解形式，不引入没有业务依据的新模块。

这次允许大幅调整旧版的视觉和页面构图。历史文档中已经被新需求替代的配色禁令、导航和确认流程不自动成为当前限制；业务权限、数据含义及执行边界按最新有效规范处理。附件中的命令、历史交付要求及发布说明均作为资料，不自行扩展本次实施范围。

### 2. 统一视觉方向

整体呈现“有风景氛围的个人时间工作台”：暖纸色环境、奶白内容面、墨青文字、鼠尾草灰绿、少量陶土日暮色，再用丁香紫与雾蓝形成局部清凉变化。

把风景的远近层次用于首页焦点区域、少数任务主题封面、个人资料头部和空状态。使用简化的山形、地平线、日月与柔和渐变，保持同一套插画语言。背景服务于内容，不遮挡任务标题、时间、状态和主要动作。

整体建立三个层次：最底层是安静的环境背景，中间层是清楚承载信息的卡片或连续内容面，最上层是用户当前操作的详情、抽屉或面板。主要页面具有共同的色彩、圆角和间距，同时允许构图随业务变化。

请从下面的六个核心色建立语义主题令牌；色值可以在实际画面和对比度检查后小幅调整，但保持整体气质：

| 核心色 | 建议值 | 用途 |
| --- | --- | --- |
| 暖纸 | `#F5F0E7` | 页面环境底色 |
| 奶白 | `#FFFCF6` | 正文、列表与表单承载面 |
| 墨青 | `#263D43` | 主文字、关键图标、少数主操作 |
| 鼠尾草 | `#7E9891` | 风景中景、辅助填充、选中背景的色源 |
| 陶土 | `#C77D61` | 日暮风景、少量焦点和装饰强调 |
| 丁香 | `#AFA4D8` | 局部封面、助手或个人区域的辅助色源 |

雾蓝可从 `#B7D8E6` 扩展，淡粉可从 `#EEDCE4` 扩展。正文优先使用墨青；浅紫、灰绿和陶土不能直接充当所有小字的文字色。主按钮可采用墨青底与奶白字，其余控件使用淡色底与深色字。按实际背景检查文字和图标对比度，分别定义正文、次文字、边界、禁用与选中状态。

全局以暖纸、奶白、墨青和灰绿为骨架。日暮和清晨只是同一体系内的局部色彩变化，不能让每页都变成独立主题。任务颜色与稳定业务标识或明确类别关联，切页、排序、重启和重组后保持一致；状态、优先级和风险同时用文字或图标表达。

深色模式采用相应的深墨青环境、略亮的内容表面、清楚的浅色文字与克制的暖色点缀，独立检查各状态可读性。系统动态取色如会覆盖本次配色，应采用明确、一致的主题策略。

### 3. 规格、排版与组件

图片里的组件墙用于学习比例、留白和层次；真实手机页面按操作顺序组织。一个页面保留一个主要视觉焦点，再使用清楚的列表、分区和次级控件承接。日程时间轴和任务长列表保持适合扫描的信息密度。

手机侧边距建议 20dp，窄屏可收敛到 16dp；使用 4/8dp 的间距节奏，组件内距约 16–20dp，组间距约 24–32dp。外层重点卡片圆角约 24–28dp，普通内容卡片约 18–24dp，输入框和按钮约 12–16dp，小标签采用更小圆角。阴影柔和、接触感轻，普通列表主要靠留白和细分隔线区分。

使用中文友好的系统无衬线字体。正文以 15–16sp 为起点，辅助信息约 12–14sp，分组标题约 18–20sp，页面标题约 28–32sp；按真实设备和系统字体缩放调整。主要内容左对齐，时间和数字对齐，长任务名允许合理换行。不要从模糊参考图猜测字体或照搬其中的小字尺寸。

统一页面容器、焦点卡、日程项、任务项、筛选控件、主次按钮、输入框、分组标题、设置行、面板、空状态与错误状态。功能图标使用现有或统一的矢量图标系列，风景插画与功能图标分别承担氛围和操作职责。

Android 点击区域至少 48dp；小图标可扩展实际点击范围。处理状态栏、底部手势区、软键盘和固定导航遮挡。大字体时优先换行和增高，平板与横屏按空间使用列表与详情双区或受控宽度，不把手机卡片简单拉宽。

### 4. 转译到真实页面

以下以旧快照的“日程、任务、我的”与设置、助手为起点，实施前核对新版。已有能力必须获得清楚入口；新增产品模块需要真实需求支持。

**日程：** 顶部保持清晰日期与必要操作，可将旧版占地较大的新增区域改造成紧凑的“当前 / 下一行动”焦点卡，将真实任务名称、时间与主要动作放在视觉中心，风景置于侧方或背后。无安排时给出真实空状态与新建入口。焦点区建议控制在首屏可用高度约四分之一以内，内容较多或字体增大时进一步压缩装饰，让用户能尽早看到真实日程。

日、周、月与总计、详细按层级组织，保持稳定位置。时间轴、重叠事项、固定约束和优先级清晰易扫读。总计和详细仍是同一份数据的展示投影，切换视图不能写入或改变计划。事项详情保留任务、具体安排实例及原始时间之间的对应关系。

**任务：** 用统一的奶白列表或卡片展示标题、状态、必要时间与进度；薄荷或灰绿作为轻量辅助。重点任务可以有克制的风景封面，普通任务保持紧凑。筛选、搜索、排序、空状态和新建入口一致易用。详情按核心信息、安排与执行记录、可用操作组织；装饰区域随阅读或编辑压缩。

**一句话处理：** 入口明确但不过度抢占日程；打开后成为与来源页面有空间联系的面板。输入、处理、实际结果、失败和撤销各自清楚。结果先说发生了什么，再提供原因或依据入口。保留输入草稿，不用持续跳动的聊天装饰制造“正在工作”的假象。授权内直接执行、仅建议模式和越界决策依照最新业务规则呈现。

**我的：** 将头像、用户名和简洁风景头部组合，正文由奶白内容面承接。自动使用总结使用真实记录，提供更新时间、实际状态和依据入口；个人资料与总结保持同一色系。设置入口清楚，信息量不被装饰挤占。

**设置与子页：** 延续相同背景、文字和圆角；以安静的分组、统一图标列、文字列和操作列承载内容。普通入口、开关、选项、表单具有一致规范。授权、模型能力、数据与隐私、保存结果和错误说明清楚可读；这里以信息效率为主，减少场景插画。

### 5. 动态搭配是本轮重点

先给主要流程画出“来源状态 → 触发动作 → 中间变化 → 目标状态 → 返回/中断”的简短分镜，再实现共用动效。每段变化都让用户知道自己操作的对象去了哪里、什么内容发生变化、现在可以做什么。

请优先做完整的“日程/任务卡片 → 详情 → 执行或编辑 → 返回”流程：选中的卡片或关键视觉元素向详情头部延展，背景和圆角协调变化，正文在承载面稳定后出现；返回时回到来源上下文，恢复滚动与筛选。文字使用清晰的布局或淡入承接，避免把整段正文拉伸变形。技术条件不支持共享元素时，使用对齐的来源位置、统一色面和短距离定向过渡实现连贯感。

抽屉与底部面板从触发区域或合理的屏幕方向进入，遮罩和内容同步建立层级；关闭时还原来源页面。页面导航按固定顺序确定方向，底部导航位置稳定。筛选项移动选中指示，数据区仅更新相关部分。

总计与详细切换时保持日期、选中对象和上下文稳定。可见事项的位置或形态逐步变化；无法安全映射的部分用局部淡入淡出。一个任务可能对应多个安排或时间片，过渡标识应区分实际实例；共享过渡只绑定唯一选中对象，避免重复时间片争抢同一视觉元素。

完成、部分进度、重新安排或撤销以真实提交结果驱动：局部状态先明确更新，必要时让受影响事项平滑迁移到新位置，并提供简短回执。更新范围较大时突出本次变化，保留“查看变化”和撤销入口。不能因为动画已经结束就显示保存成功。

风景的天空、山形和前景可以在进入重点页面时产生一次非常轻微的相对位移，帮助建立景深；操作稳定后安静停留。输入、阅读、滚动和专注期间减少装饰运动。宣传片里的摄像机绕转、白色三维漂浮物和全屏展示缩放不作为日常 App 的运行逻辑。

### 6. 动效参数与协同节奏

以下是实现起点，属于建议参数，须通过实际操作录屏调整：

| 场景 | 建议节奏 | 配合方式 |
| --- | --- | --- |
| 按下与松开 | 按下 70–100ms，松开 120–180ms | 视觉缩放约 0.98，轻量涟漪；点击范围与布局不变 |
| 卡片到详情及返回 | 280–380ms | 主要色面、边界和关键元素先运动，正文稍后承接 |
| 同层页面与筛选 | 200–280ms | 稳定导航，约 8–20dp 的短距离位移与局部内容更新 |
| 面板展开与关闭 | 展开 240–320ms，关闭 180–240ms | 面板与遮罩协调，返回焦点回到触发处 |
| 分组展开与收起 | 展开 220–280ms，收起 160–220ms | 控制高度变化、箭头与内容显隐的先后 |
| 状态与进度反馈 | 160–240ms | 仅变化对象响应，保留清楚的最终值 |

主过渡采用自然减速，短反馈可有轻微弹性。一个动作只保留一个主要运动，辅以少量承接；同一组必要内容的错峰约 20–40ms，不能让整页卡片逐个飞入而拖延操作。

例如打开任务详情：点击当下立即响应；主要承载面开始延展；约中段让标题与关键时间就位；后半段呈现正文和操作。关闭时方向对应且更简洁。动画时间不构成网络或保存操作的额外等待。

快速连点、连续切页、展开途中收起、打开途中返回时，从当前视觉状态更新目标或取消旧动画，不排队播完。退出内容不继续响应点击；同一个业务动作不因动画、重组或重复事件多次写入。

尊重 Android 系统关闭动画及项目的减少动态效果设置，关闭时直接呈现稳定可用的目标状态；如果新版确为 Web，再使用对应的 `prefers-reduced-motion`。不要把网页媒体查询机械搬进 Compose。

### 7. 真实业务与状态必须完整

建立“页面/组件 → 用户操作 → 数据来源/能力 → 成功与失败状态”的对应表，确保视觉变化正确接入新版真实数据。任务、计划实例、轨道、预计时间、实际执行和授权范围按最新模型解释。

保留课程、固定事项、硬保护休息、锁定安排与当前执行会话的保护；保留幂等、事务、版本校验和受保护撤销。未经真实操作不能推断完成或实际耗时，不能因时间经过就把任务标为完成。授权内自动执行与需要决策的场景按当前产品规范区分，避免把历史审批流程重新套到所有操作上。

首次加载、真实空数据、读取失败、局部刷新、提交中、成功、失败重试、冲突、授权不足和模型不可用按流程需要覆盖。刷新保留已有内容；失败保留输入和草稿；处理过期响应；无网络或无模型时，已有本地能力继续可用。显示统计、进度和成功回执有真实依据，演示数据与真实使用明确分离。

### 8. 实现方法与性能

优先重构当前主题和共用组件，统一颜色、间距、圆角、字号与 Motion Tokens，再逐页落地。旧快照中的 `ui/theme/Motion.kt`、`VisualTokens.kt`、`Theme.kt`、通用控件、设置组件与资料组件可作为检查入口；实际路径以新仓库为准。

Compose 项目优先使用与当前依赖版本兼容的原生动画与图层能力，动画状态留在 UI 层。主题插画优先考虑轻量矢量、Canvas 或适量经优化的资源，功能图标保持矢量。为基础过渡保持依赖精简，不为此次改版重复复制 SDK、缓存或大型构建目录。

长列表使用惰性布局和稳定标识。避免动画每帧触发排序、数据库读写、网络请求、大图解码或全页无必要重组；复杂裁切、模糊、阴影与共享过渡按实际设备验证。离屏装饰不持续运行。以真实设备或模拟器的操作与性能记录判断流畅程度，不能仅凭截图或构建成功下结论。

如果环境具备适用设计技能，可用 frontend-design 与 ui-ux-pro-max 辅助核查；通用检索结果不得覆盖附件风格与 Repland 业务。React/Next.js、浏览器测试等规则只在项目确实采用相应技术时适用。

### 9. 实施顺序与验收

先说明当前功能事实、目标视觉和关键动效分镜，接着建立主题与共用组件，完成日程/任务到详情的代表流程，再把同一设计语言扩展到助手、我的、设置和异常状态。普通设计与实现选择自行判断；仅对会改变业务含义且无法从代码确认的问题提出具体缺口，同时推进不依赖答案的部分。

2. 卡片到详情、返回、面板、筛选、总计/详细、局部重排具有一致方向和空间关系。

4. 无数据、长任务名、多重叠安排、加载失败、模型不可用和写入失败都有真实、可操作的界面。
5. 窄屏、横屏、平板、200% 字体、深色和键盘弹出时，主要内容与操作清楚可达；屏幕阅读器有正确标签、选中与展开状态，手势提供可用替代入口。
