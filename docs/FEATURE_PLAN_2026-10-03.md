# 任务自动排序与全应用助手联动方案

日期：2026-10-03（Asia/Shanghai）
状态：设计记录，待用户确认实施。用户本轮只授权记录与设计；未修改应用代码、未接入或调用远程 API。

## 1. 任务页自动排序（上一轮方案记录）

- 将“全部任务”右上角“语音添加”替换为“自动排序”，沿用绿色文字按钮；语音输入移动到“＋添加任务”流程。
- 点击打开排序预览，展示建议顺序、可展开的排序依据和上下调整；提供“应用排序 / 取消”。
- 复用 `LocalPriorityRanker`：初始优先级、类别偏好、截止日期、延期次数；离线可用，分数相同时使用现有稳定次序。
- 统一排序所有未完成任务；总览、待安排、今天、逾期使用同一顺序的筛选结果，已完成页维持原展示。
- 应用后持久化，重启保留。任务页“自动排序”只调整列表；助手“制定计划”独立执行新一轮排序与排程，不要求先在任务页排序。已有手动顺序时，预览明确提示替换范围，确认后才替换。
- 排序不改初始优先级、任务状态和已有日程时段。计划预览可提出基于新顺序的时段建议。
- 不足两项可排序任务时禁用；成功显示“已排序”并可撤销；失败保留原次序。
- 撤销只回退本次排序，不覆盖之后新增任务或其他修改；新的修改出现时应检测版本并给出适用范围。

## 2. 当前助手的代码事实与问题

- `AgentCenterScreen` 中“安排今天 / 新增事项 / 调整草案”均调用 `onSeed`，仅追加前缀，没有进入独立工作流。
- 该页面主要接收日期、当天占用事件和 AI 精化回调；不直接接收完整任务库、统一排序、当前可编辑计划草案及完整设置。
- 现有入口通过分别保存任务、分别放置时段的回调提交，尚不是一次完整操作的原子提交。
- “我的”已经有 AI 开关、服务地址/模型/Key、类别偏好、参与方式、提醒、画像证据和数据管理；一些设置已有连接，不能将“所有页面完全不关联”当作代码事实。
- 当前工作区有独立的 PlanningAgent 和 ArrangementAssistant 路径，网络 Advisor 通过 debug 实现注入；有 Key 不等于所在构建一定支持远程能力。
- 较旧 README/交接的离线描述与当前代码和 `REPLAND_IDEA.md` 正式 BYOK 路线存在差异。实施时须统一构建能力与文案，不能仅改变按钮。

## 3. 产品目标与权限范围

助手成为整个 Repland 的统一操作入口：用户通过自然语言查询、创建、编辑、排序、安排、调整偏好、打开页面，并能看到真实操作结果。所有页面使用同一任务、计划和设置来源。

“控制整个程序”按应用内业务能力实现，而不是让模型直接操作数据库或执行任意代码：

| 能力 | 设计行为 |
| --- | --- |
| 查询、解释、导航 | 可以直接读取授权范围内的数据，返回真实结果或打开指定页面。 |
| 创建/编辑任务、批量拆分、列表排序 | 形成结构化操作预览，用户确认后统一提交。 |
| 放入轨道、移动时段、调整日程、恢复计划 | 形成可编辑计划差异，确认后创建新版本。 |
| 类别偏好、参与方式、提醒设置 | 用户明确提出修改后展示新旧值，确认后更新同一设置源。系统通知权限仍走 Android 授权。 |
| 开始/完成/延期/取消任务、执行反馈 | 必须来自用户明确表达的意图；助手不得仅因时间到了推断完成。展示目标任务和必要字段后确认。 |
| 删除任务、清空数据、导出 | 精确展示对象和影响，保留专门确认或系统文件选择流程。 |
| API Key 与 AI 授权 | 只通过专用设置界面输入；助手不读取 Key、不在对话中索取 Key、不自行开启 AI。 |

首版保留“预览 → 确认”的统一写入流程；已有“由 AI 决定”只授权当前明确冲突，不扩展为长期自动控制。历史、初始优先级、锁定时段和用户手动并行安排保持受保护。

## 4. 独立制定计划与对话框下属工作流

页面先展示独立的“制定计划”主按钮/卡片，其下展示“说出你的安排”对话框。“安排今天 / 新增事项”仍放在该对话框内部、输入区域下方，作为对话的下属功能。三个按钮不放在同一行；原“调整草案”快捷按钮移除。

### 制定计划

1. 点击即读取现有未完成任务，主动重新排序并分配时段，直接生成完整计划预览；无需先点任务页自动排序，也无需在“说出你的安排”中输入或发送消息。
2. 排序结合初始优先级、类别偏好、截止日期、延期记录及有效任务上下文；排程结合预计剩余时长、可用时间、课程、休息、固定事项、锁定段和“我的”相关设置。AI 可用时提出排序与规划建议，不可用时走本地确定性排序和排程。
3. 默认沿用现有 30 天滚动规划窗口，用户可缩小范围。输出包含建议任务顺序、具体时段、待安排项及原因；硬约束或容量不足时明确提示，不删除任务或覆盖锁定段。
4. 时长或可用时间不足时提供补充卡，仍输出建议顺序及待安排项，不虚构具体时段。没有任务时引导“新增事项”。
5. 使用已有任务引用，不重复创建任务；新顺序可与原顺序不同，预览标明重排及受影响的手动顺序，确认后才替换。已有未提交草案时先提供继续编辑或重新制定的选择。
6. 确认后将新排序和新计划作为同一次变更提交，同步任务页、首页轨道、计划历史及提醒；取消保留原顺序和原计划。
7. 该入口独立于对话框：不读取尚未发送的对话内容、不插入前缀、不清空或改写输入。生成结果可在预览内手动编辑或继续对话调整。

### 安排今天

定位为单日安排；与“制定计划”的跨日整体规划区别明确。已有计划时优先沿用其中的今日安排，只对用户选定的今日范围提出调整。

1. 点击即加载今天任务、待安排任务、当前任务顺序、时间轴占用、锁定段和最新设置，显示加载状态。
2. 不需要用户重新列出现有任务；任务与可用时间足够时直接生成可编辑安排预览。
3. 缺少必要时长或可用时间时，显示只针对缺项的补充卡；信息不足的任务仍可排序，不能假造具体时段。
4. 展示“安排了哪些任务、移动了哪些时段、哪些仍待安排、为什么”，允许排除任务和局部调整。
5. 确认后首页轨道、任务页和提醒使用同一已确认版本；提供“查看今日安排”。

### 新增事项

1. 点击进入事项收集模式，输入框显示对应引导，不向正文插入前缀。支持文字或语音和一次多项录入。
2. AI 输出可编辑任务卡，识别标题、描述、类别、优先级建议、截止日期、时长和可能关联的已有任务。
3. 缺项按需补充，可能重复的事项提供“新建 / 更新已有”选择，不能静默覆盖。
4. 提供“加入事项库”与“加入并安排今天”；前者只建任务，后者同时预览任务及放置时段。
5. 确认时一次提交任务和相关安排，失败整体回滚，避免只有任务落库或只有部分时间段写入。

独立“制定计划”绑定一键排序与排程意图；对话框下的“安排今天 / 新增事项”绑定各自的对话工作流，不只是追加前缀。后续自然语言可追加修正或切换对话意图；切换时保留已有输入，已有未提交草案时提供继续、另存或放弃选择。

调整草案仍作为计划预览内的对话和编辑能力保留，不再作为首页的独立快捷按钮。

## 5. “我的”设置与各页面的联动

| 设置或数据变化 | 联动结果 |
| --- | --- |
| AI 开关、模型、接口、Key | 助手和任务详情统一显示配置/连接状态；关闭 AI 或清除 Key 立即取消远程请求，防止迟到结果应用。新请求使用最新配置。 |
| 类别偏好 | 任务自动排序与助手排程共用权重；旧预览标为需刷新，当前已确认顺序与日程保持到用户确认替换。 |
| 重度参与 | 展示完整排序理由、时间轴、差异和编辑控件。 |
| 适度引导 | 优先显示关键变动、风险和确认操作，可展开详情。 |
| 轻量执行 | 优先显示接下来三项和简洁摘要，完整计划仍可查看；不降低用户确认要求。 |
| 提醒开关/系统权限 | 同步已确认计划的提醒；草案不产生通知，关闭后取消已安排提醒。 |
| 画像证据生成/更正/删除 | 后续请求只使用允许使用的最新有效证据，显示采用的依据；不暗改初始优先级或类别权重。 |
| 手动排序、轨道拖动、任务编辑/完成 | 助手读取最新状态，当前旧草案标记过期；重新计算只生成草案，保留用户锁定与手动决定。 |
| 课程/休息/固定事项变动 | 刷新真实占用，提示受影响草案；自动排程尊重硬约束，不自行创造并行冲突。 |
| 清除本地数据 | 清理相关草案、对话业务引用、缓存与提醒，任何在途回复失效；Key 清除范围需与专用设置和实际清除文案一致。 |

典型闭环：在“我的”调高课内学习权重 → 点击独立“制定计划” → 依据新权重重新排序并结合真实时间约束生成计划 → 用户确认 → 任务页新顺序、首页轨道与提醒同步更新。任务页“自动排序”可单独使用；对话框下的“安排今天”提供单日安排入口。

## 6. 共用数据与操作层设计

- 增加应用层协调服务，统一读取 Repository 流；页面不再各自复制任务、计划和偏好。
- 独立保存任务顺序，供任务列表与计划生成共用，避免必须先有一个时间计划才可持久化排序。
- 草案从页面内部临时状态升级为统一可恢复的数据；切换页面、旋转、重启后可继续编辑。
- AI 上下文包含本次必要的任务、有效反馈、排序、当前计划/草案、硬约束、相关设置与画像摘要。采用请求内引用，不发送 Key，按任务范围提供数据。
- AI 返回结构化业务操作，交由类型、字段、任务引用、硬约束、锁定、手动顺序、版本和权限校验；文本解释不能代替实际操作。
- 每项操作明确目标、参数、理由、依赖和涉及的版本；缺字段或歧义时提出补充卡。
- 同一个命令服务处理 UI 手动操作和助手确认操作；调用已有领域校验，并集中处理可恢复错误。
- 批量数据库变更在同一事务中提交；提醒等外部副作用在提交后同步，失败可重试且不重复写业务数据。
- 请求与确认绑定任务/计划/设置/草案版本。生成期间用户修改数据则标记过期，确认时重新校验，禁止旧响应覆盖新修改。
- 使用操作标识防止重复确认与重复回调；记录业务变更及结果，可恢复支持版本化的计划/顺序；不可撤销操作不得显示误导性的撤销。
- 联网能力、设置页状态和实际 Advisor 必须一致；支持结构化工具调用的接口用工具契约，其他兼容接口使用结构化响应并走相同本地校验，不因更换供应商绕过规则。

## 7. 助手页面的呈现

- 顶部显示日期、AI 状态与配置入口；明确区分“AI 可用 / 未配置 / 当前构建不支持 / 本地模式 / 请求失败”。
- “制定计划”独立展示在“说出你的安排”对话框上方；对话框内输入区域下方保留“安排今天 / 新增事项”。主体显示上下文摘要、进度、补充卡、操作预览和确认结果。
- 发送后显示“读取任务 → 生成建议 → 检查冲突”的真实状态，可取消；多轮输入编辑统一草案。
- 结果用任务/日程/设置卡片呈现，不仅输出聊天文字。应用成功显示实际影响数量并可跳转对应页面。
- 网络失败保留输入和编辑内容，提供重试或本地排序/规划；不显示虚假的“执行成功”。
- 未配置 API 时可以使用本地能力，并链接到“我的 → AI 设置”；配置完成后返回原工作流。

## 8. 实施顺序（本轮仅记录）

1. 统一业务操作、上下文读取、任务顺序与可恢复草案，明确模型适配器与构建能力。
2. 落地任务页自动排序；与“制定计划”共用排序能力及已确认顺序存储，但制定计划会重新排序。
3. 实现独立“一键制定计划”与对话框下属的两个工作流，先验证完整联动及原子提交。
4. 接入统一 AI 结构化操作路径、连续对话、上下文版本校验与取消/降级。
5. 逐步覆盖任务编辑/生命周期、时间约束、计划恢复和设置操作，补齐导航、结果与权限边界。

## 9. 验收场景

- “制定计划”在对话框外、上方独立显示；“安排今天 / 新增事项”在对话框内、输入区域下方，原“调整草案”快捷入口已移除。
- 对话框为空也可点击“制定计划”，直接重新排序现有任务并生成跨日计划；不需要先进行任务页排序，不重复创建任务。
- 对话框有未发送内容时点击“制定计划”，输入保持原样且不参与本次计划；按钮不插入前缀。
- 新计划预览展示排序及时间变化，确认后任务顺序、各页面与提醒使用同一变更结果；取消不改变原顺序或计划。
- 现有手动顺序与建议顺序不同时明确展示差异，缺信息时输出建议顺序和待安排项，容量不足时说明原因。
- “安排今天”无需重新输入已有任务即可产生预览，确认后任务列表、首页轨道、计划历史、提醒一致。
- “新增事项”一次录入多项，确认后数量准确；重复确认不重复创建；任务+时段提交失败无半成品。
- 计划预览中的草案调整复用已有任务和草案，连续修改、跨页返回与重启均不丢；取消不改变当前计划。
- 修改类别权重后新排序与新规划使用相同权重；旧预览提示过期，不覆盖已确认计划。
- 切换参与方式改变助手信息密度；提醒开关影响实际提醒；配置/模型变更影响下一次真实请求。
- AI 关闭、无有效配置、超时、断网或非法输出时，保留数据并可回退本地；晚到回复不能重新写入。
- 在 AI 返回前手动拖动轨道或完成任务，确认旧预览应被拦截并重新生成。
- 模型请求完成任务、移走锁定段、覆盖课程或改初始优先级时，按用户意图与操作权限检查；无授权则拒绝执行。
- 恢复历史计划后所有页面与提醒同步；画像证据更正/删除后新请求不再引用旧证据。

本方案覆盖功能设计与未来实施约束，不表示功能已经实现；此前缺陷清单继续独立维护。
