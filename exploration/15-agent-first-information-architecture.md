# Repland 信息架构与执行界面重构（探索稿）

## 结论先行

本轮不把更多能力堆到首页。产品的中心是“把一个可复用事件变成当天可执行的时间实例”，而不是一个同时承担输入、回顾、设置与计划生成的超级页面。

| 模块 | 用户问题 | 本轮职责 | 刻意不做 |
| --- | --- | --- | --- |
| 今日 | 我现在最该看什么？ | 只展示下一时间块与同一时刻的并行事项；进入专注 | 把完整清单、语音、日回顾都塞进首页 |
| 日 | 如何把事情放入今天并执行？ | 轨道、时间标尺、事件库、备注/状态入口 | 用卡片列表伪装时间关系 |
| 周 | 这一周是否失衡？ | 七日负荷、固定课与日常事项混看、连续周切换 | 复制日视图的缩略版 |
| 月 | 我这个月的模式是什么？ | 占用、完成、类别、状态四种投影 | 用无语义的同色圆点 |
| 任务 | 事情本身进展如何？ | 任务对象、进度、截止与复用 | 强迫用户在完成时补齐日志 |
| 安排 Agent | 我用自然语言说完后如何得到可控结果？ | 将语音/文本变成可编辑预览；每一次写入均需确认 | 自主写入日程或泛化为聊天机器人 |
| 时间工作台 | 课表与限制在哪里维护？ | 从 Agent 或设置进入的配置工具 | 占据主导航 |

## 交互模型

### 事件对象与实例

任务先作为事件对象存在，未必属于某一天。用户把它拖到日轨道，或点击“安排到当前时段”，才建立可移动的排程实例。相同事件可以在不同日期或轨道重复安排，历史与进度仍归属于同一个任务。

### 轨道：音乐编曲的有用类比

借用音乐工作站的三个部分，而不照搬其复杂度：

1. 轨道表示平行语境（课程、专注、生活，或用户新建的轨道），不是自动分类器。
2. 片段的纵向位置是时间，横向列是并行轨道；重叠因此可见而不被强制消除。
3. 事件库是可复用素材箱。长按拖动需要实时跟手和目标时间反馈；点按安排是等价的单指替代方案。

拖动落点会依据横向位移选择轨道、依据纵向位移按 15 分钟对齐时间，并在落下前显示目标。点击事件库项目会将它放到“当前时刻 + 默认轨道”；两者均创建实例，绝不直接修改任务本体。

### 专用 Agent 的权限边界

Agent 不是“替你管理人生”的聊天框，而是输入与工作流的编排器：

- 输入：自然语言、可编辑语音转写、快捷意图。
- 输出：任务草案、计划草案、任务拆分与检索结果。
- 保护：预览不写入；“确认创建”才保存任务；“生成计划”仍进入现有草案确认流程。
- 降级：无联网模型时，输入仍可被本地结构化为草案，明确标识为本地预处理，不伪称 AI 结论。

## 月度四种投影

- **占用**：以单元格填充深浅显示当天总排程分钟数，回答“哪里拥挤”。
- **完成**：以水位显示已确认完成任务占比，回答“推进到哪”。
- **类别**：用少量色条显示课程、任务、固定/生活事项组合，回答“时间花在何处”。
- **状态**：使用进行、待确认、完成三种可辨形态，回答“是否需要处理”。

颜色从不单独承载意义；每种投影都配有文字图例。

## 验证标准

1. 初次用户在 10 秒内能找到“下一件事”。
2. 事件不需要先填具体位置，既可拖放也可点按安排。
3. 语音内容在保存前始终可编辑，Agent 不能绕过确认。
4. 课表与普通事项在日、周、月里使用同一时间事实来源。
5. 小屏下底部导航不超过四项：今日、任务、Agent、我的。

## 对抗性审查（实施前）

- **风险：轨道像“高级功能”而非日常工具。** 处理：默认轨道和点按安排先可用；新建轨道是渐进出现的能力。
- **风险：Agent 让人以为会自动写入。** 处理：每一张预览都把“尚未写入”作为主提示，确认动作单独命名。
- **风险：月度数据被过度解读。** 处理：只基于已确认状态展示完成，不从打开、停留或时间经过推断完成。
- **风险：首页为简洁牺牲了发现性。** 处理：下一时间块直接进入专注；事件库和完整时间轴保留在日视图，Agent 固定在主导航。
