# 前端重构与验收记录

日期：2026-09-26。此记录对应已写入 Android Compose 的界面，不是视觉概念稿。

## 页面与组件

| 区域 | 重构前 | 当前实现 |
| --- | --- | --- |
| 今日 | 多种内容争夺首屏 | 专注概览与完整日程分开；当前任务突出，语音入口固定在标题栏 |
| 任务总览 | 每项展开全部属性 | 真实数量摘要、两行任务条目、按状态分组；默认每组三项，可展开全部 |
| 任务完成 | 强制填写完成内容与完成时间 | 点击完成即结束；执行时长由开始日志推断，计划时长作为无开始记录时的回退；复盘内容改为完成后可选补充 |
| 创建 | 全量表单 | 输入 → 意图 → 时长或截止时间；最后确认才写入 |
| 详情 | 标题、信息、动作权重接近 | 状态与标题突出，描述按需显示，类别等作为次级信息，主次动作分层 |
| 时间 | 多个说明块与入口平铺 | 计划状态主卡、固定安排入口、课程与日期例外列表 |
| 全天视图 | 纵向项目列表 | 00:00–24:00 时间网格，课程、任务、休息按轨道并行呈现；点开块后才显示详情动作 |
| 轨道 | 只有算法自动分组 | 顶部轨道条展示当前节奏，可新增并命名“运动/语言学习”等自定义轨道；轨道头与时间块严格对齐 |
| 事件生命周期 | 创建时直接绑定时间位置 | 先进入事件对象库，再被编排到日轨道；同一事件可被复用到多个日期或不同轨道 |
| 周 / 月 | 只有当天明细 | 周视图看七天节奏分布，月视图看密度、留白和拥挤日；从月格点入当天轨道 |
| AI | 多个独立能力按钮 | 一个“打开对话”入口；建议动作作为输入提示，提交后由请求类型映射到既有 agent/tool 能力 |
| 编辑 | 窄弹窗中堆叠字段 | 任务、时间块、日期例外、反馈、计划草案与历史采用共享底部抽屉 |
| 设置 | 模式大卡与全部配置字段平铺 | 模式分组列表，提醒和助手开关，偏好、画像和数据管理按需展开 |
| 品牌 | 默认 Android 自适应图标 | 墨绿底、三条错位时间轨道与暖色节点的矢量自适应图标（Android 8+） |

## 视觉与交互决策

- 基于 UI/UX Pro Max、Apple design 和 Emil design engineering 的原则落实信息层级、原生触控、渐进披露与短过渡。
- 使用纸色背景、墨绿主色、白色内容表面；重点任务卡使用轻微渐变，不在普通任务行中重复主色大块。
- 补齐浅色与深色 surface、outline 及容器文字颜色，避免组件落回不一致的默认色。
- 统一标题字阶及行高；重点容器 22–24dp 圆角，普通条目 14–18dp；主要图标操作保留 48dp 触控面积。
- 创建步骤使用短淡入与小幅位移；抽屉使用 Compose 原生移动与系统返回行为。
- 计划排序改为长按拖动，避免普通纵向浏览触发排序；保留上下移动按钮。排序依据可展开查看。
- 共享编辑抽屉限制内容高度，滚动区和底部确认区分开，避免长表单将动作推到不可见区域。
- 任务完成遵循“先结束、后复盘”：完成动作只改变状态并写入最小执行记录，反馈、完成内容和校正时间均可在当天复盘或任务历史中补充。
- 时间轴使用连续视觉坐标表达一天，而不是把时间信息藏在多层卡片里；并行事项采用轨道，避免课程与任务互相覆盖后失去可读性。
- 轨道控制遵循“先看、后配”：已有轨道直接以轻量标签显示，新增轨道只要求一个名字；不会在创建轨道时强制用户迁移既有任务，后续可再增加拖拽或批量归类。
- 事件对象与排程位置解耦：任务本身保存目标、描述和估计时长；日程段保存某一次发生的日期、时间和轨道。这样复制课程、复用学习事件、调整今天而不改变事件本体都成立。
- 三层时间视图形成不同的认知缩放：日视图负责执行与拖放，周视图负责平衡多个轨道，月视图负责发现密度趋势和恢复空间；不把月视图做成缩小版日视图。

## 竞品取经与边界

- [Structured 官方页面](https://structured.app/) 将待办、日历和时间线合并到一个连续的日程视图；本项目取其“先看节奏、再看细节”的信息层级，但保留课程与任务的并行轨道。
- [Sunsama 的 time-blocking 指南](https://www.sunsama.com/blog/time-blocking-tips) 强调小时间块、缓冲和计划/实际的对照；本项目将实际时长作为后台记录和复盘数据，不把它变成完成任务前的阻塞表单。
- WakeUp 课程表的公开对照资料可参考[第三方截图说明](https://www.hackhome.com/info/558988.html)：其价值在于课程块的高密度可扫读；本项目吸收“按周/日快速定位课程”的方向，但把课程与个人任务统一到全天时间轴中。

## 功能保全与对抗性审查

1. **精简后是否丢掉能力？** 补回完整日程的显式入口；继续使用现有并行轨道、计划、画像与记录模型。设置折叠只影响展示；AI 能力不再由多个按钮暴露，而是收敛到对话入口。
2. **是否把经过计划开始时间伪装成已执行？** 当前卡使用“计划时段内”，执行状态仍来自任务记录。
3. **图标是否误导？** 未开始任务用播放图标，不再复用已完成的勾选图标。
4. **是否提前保存草稿？** 分步选择时不写入任务；测试验证时长确认前不存在任务，确认后正确保存 30 分钟及日期。
5. **是否存在重复点击目标？** 区分当前任务主卡与普通列表的测试标识，语音入口保留单一稳定测试标识。
6. **完成是否仍然被数据采集阻塞？** 不阻塞；完成按钮只做状态变更和最小日志写入，实际时长优先取开始日志，未开始时回退到计划时长。
7. **全天视图是否只是把列表换了皮？** 不是；布局坐标直接由开始/结束分钟和轨道计算，当前时间线、并行关系、详情展开均在同一坐标系表达。
6. **界面是否夹带实现说明？** 移除设置页固定显示的“当前 APK 未配置”判断；具体请求结果由现有请求流程反馈。
7. **验收边界：** 本轮不声称完成所有设备与字体倍率的视觉验证。深色配色已实现，但完整深色、大字体、横屏及 TalkBack 回归仍需覆盖。日期例外和传统编辑字段的日期输入仍沿用原有实现；新建流程提供快捷日期。
8. **仍需领域层解决：** “今天”快捷创建目前使用既有截止日期字段承载，没有新增独立的意向安排日期字段；应在后续领域演进中拆分安排意向与硬截止时间。本轮不把这一语义缺口描述为已解决。
