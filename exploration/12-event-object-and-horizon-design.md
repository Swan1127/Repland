# 事件对象与三层时间视图设计

## 核心转变

事件和排程位置必须拆开：

- 事件对象：标题、描述、目标、估计时长、类别、重复规则、可复用内容。
- 排程实例：某个事件在某一天、某个时间段、某条轨道上的一次放置。
- 执行记录：用户实际开始、完成、延时、跳过和复盘内容。

创建事件时只创建“对象”，不要求填写日期、时间和轨道。事件对象进入事件库，之后可以被拖到任意日期和轨道，也可以重复放置。拖动只改变排程实例，不修改事件本体。

## 三层视图

### 日：音乐音轨式执行台

- 左侧是时间刻度，横向是多个轨道。
- 事件块的纵向位置代表开始时间，高度代表预计持续时间。
- 轨道头显示“课程、专注、生活、运动”等节奏集合。
- 事件库位于时间轴上方或底部抽屉；拖动事件对象到轨道后，再根据纵向位置吸附到 5 分钟或 15 分钟刻度。
- 拖动释放后只生成一个排程实例，原事件对象仍保留在事件库中。
- 点击事件块进入详情；长按打开移动、复制、拆分和删除本次排程。
- 当前实现已经提供全天时间网格、轨道头、轨道新增和时间状态；下一步接入事件库拖放与排程实例持久化。

### 周：七日编排矩阵

- 每一天是一张轻量卡片，横向滚动查看七天。
- 卡片只显示事件标题、时间和颜色，不展示描述等深层信息。
- 重点是比较“哪天拥挤、哪天有恢复空间、哪条轨道连续过载”。
- 事件可以从某一天复制到另一日，也可以拖动到另一日后再进入日轨道微调。
- 当前实现已提供七日横向节奏卡，并复用同一套事件计算模型。

### 月：密度与趋势概览

- 月视图不是缩小版日视图，而是密度地图。
- 每个日期格显示事件数量和不同轨道的颜色点。
- 颜色点仅用于快速识别，数量和选中状态必须同时由文字表达，避免只依赖颜色。
- 点击日期后进入该日轨道；从月视图不直接编辑复杂事件。
- 月视图为后续 Agent 提供“本月过载日”“连续学习节奏”“空白恢复日”等分析入口。

## 拖放规则

1. 事件对象拖出时显示原卡片的半透明影子。
2. 轨道接受区在拖动时提高对比度，但不改变整个页面布局。
3. 时间吸附步长默认 15 分钟，用户可在设置里切换 5/15/30 分钟。
4. 若与固定课程冲突，不直接阻止拖放，而是显示冲突层，让用户选择继续、缩短、移动或交给 Agent 建议。
5. 触屏拖动之外，必须保留“放置到轨道”和“选择时间”的非拖动入口，满足可访问性和单手使用。
6. 复制事件与移动事件必须明确区分：复制保留原实例，移动只改变当前实例。

## Agent / Workflow 接入点

- Agent 可以根据对话创建事件对象，但不应未经确认直接改变排程实例。
- Workflow 可以把事件对象复制到一周中的多个日期，再由用户确认具体时间。
- Agent 可以读取执行记录和排程偏差，提出“调整轨道”“延长缓冲”“降低重复频率”等建议。
- 用户确认后才写入排程；执行状态、完成状态和复盘记录继续由用户和本地系统掌控。
